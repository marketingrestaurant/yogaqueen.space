# CLAUDE.md

Инструкции для работы в этом репозитории. Контекст проекта — см. [README.md](README.md).

## Что это за проект

Репозиторий генерирует HTML для лендингов Yoga Queen (Анна Корчагина), которые вручную вставляются в кастомный HTML-блок Tilda (T123 / Zero Block). Это не standalone-сайт с деплоем — здесь нет сервера, сборки, фреймворка.

## Жёсткие правила

1. **Один лендинг = один самодостаточный HTML-файл** в `landings/<slug>.html`, слаг — по названию оффера (например `retreat-bali`, `kite-safari`, `free`).
   - CSS и JS — инлайново внутри файла (`<style>`/`<script>`), либо через `<link>`/`<script>` на внешние CDN. Не полагайся на относительные пути к другим файлам репозитория — при вставке в Tilda файл живёт изолированно от остального репо.

2. **Структура секций не меняется** между лендингами — меняется только контент. Канонический порядок (см. README и https://yogaqueen.space/free):
   1. Hero + форма захвата лида (above the fold, обязательно на первом экране)
   2. Преимущества оффера
   3. Программа / что входит
   4. Как это работает
   5. Об инструкторе (Анна Корчагина)
   6. FAQ
   7. Юридический дисклеймер (RU/EN, ANDIKO s.r.o., Прага)
   8. Футер (соцсети, подписка, копирайт, политика/условия)

   Если для конкретного оффера какая-то секция не нужна — не удаляй её из структуры по своей инициативе, сначала спроси.

3. **Mobile-first**: вёрстай и проверяй сначала под мобильный вьюпорт, потом десктоп.

4. **Форма захвата лида должна быть видна без скролла** — и на мобильном, и на десктопе.

5. **Аналитика/пиксели** — в каждый лендинг по умолчанию закладывай заготовки для:
   - Google Analytics 4 (gtag.js)
   - Google Ads (конверсионный тег)
   - Meta Pixel (Facebook/Instagram)

   ID/токены — плейсхолдерами (`GA4_MEASUREMENT_ID`, `GOOGLE_ADS_CONVERSION_ID`, `META_PIXEL_ID`), с явным комментарием, что их нужно заменить. Реальные ID пользователь даёт отдельно. Никогда не выдумывай реальные ID аналитики.

6. **SEO** на каждом лендинге: `<title>`, meta description, Open Graph + Twitter Card, canonical, разметка schema.org (Organization/Course/Event/FAQPage — где уместно).

7. **GEO** (в двух смыслах сразу):
   - Generative Engine Optimization: прямые чёткие ответы на вероятные вопросы в тексте и FAQ, структурированные данные (FAQPage schema), понятные заголовки-вопросы — чтобы AI-поисковики могли точно процитировать контент.
   - Гео-таргетинг/локализация: учитывать регион/язык аудитории оффера (валюта, часовой пояс мероприятия, hreflang при мультиязычности).

## Как проверять работу

Деплоя и сервера нет. Проверяй, открывая HTML-файл напрямую в браузере (preview/navigate на `file://.../landings/<slug>.html`), в первую очередь в мобильном вьюпорте, затем в десктопном.

## Что НЕ делать

- Не подключай фреймворки/сборщики (React, Vite и т.п.) — Tilda-блок принимает только чистый HTML/CSS/JS.
- Не строй серверную логику — форма должна отправлять данные туда, куда укажет пользователь (Tilda forms / Telegram-бот webhook / CRM); если интеграция не указана явно — спроси, куда слать лид.
- Не меняй реквизиты и текст юридического дисклеймера (ANDIKO s.r.o.) без явного подтверждения пользователя.
- Не выдумывай ID аналитики/пикселей и другие секреты — только плейсхолдеры или значения, явно данные пользователем.
